    Quickstart¶

    This page takes you from nothing to a working connection. Buyers install the public pewter CLI and sign in against the staging API (Buyer tab). The seller agent is not published and still runs from source (Seller tab). Production API access remains invite-only.

    Access

    Public sign-up is coming soon. Today accounts are created by invitation (a waitlist exists at POST /api/v1/waitlist). The public CLI also requires an existing Pewter app account to approve a device login.

    1. Install the agent (Node.js 22.18 or newer). This is the seller agent, not the public pewter CLI in the Buyer tab. A published package is coming soon; today the agent runs from source:

    node --version            # must be >= 22.18
node src/cli.ts version   # from the pewter-node-agent source folder

    2. Create a draft listing (details):

    curl -X POST https://api.example/api/v1/listings/create \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: my-first-listing" \
  -d @listing.json

    3. Get a pairing code for that listing:

    curl -X POST https://api.example/api/v1/nodes/pairings \
  -H "Authorization: Bearer <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: pair-1" \
  -d '{"listing_id": "LST-..."}'

    4. Check what the agent sees (detects NVIDIA, AMD or Apple silicon GPUs):

    pewter-node-agent measure

    5. Connect the machine:

    pewter-node-agent up --code XXXX-XXXX --api https://api.example/api/v1 --name rack-01

    The agent prints Paired as NOD-… for listing LST-… and starts heartbeating. Then ask Pewter to revalidate: POST /api/v1/listings/{id}/revalidate.

    Replace https://api.example with the API host you were given. The public production host is not published.

    1. Install the public CLI (pewter, alias pew). v0.1.0 is read-only, talks only to the Pewter staging API, and refuses production.

    On macOS (the supported Mac install; darwin binaries in 0.1.0 are not notarized):

    brew trust --formula omegacomputes/tap/pewter   # Homebrew 7; required before the formula will load
brew install omegacomputes/tap/pewter

    On Linux, and on macOS once OpenSSL 3 is first on PATH:

    curl -fsSL https://omegacompute.com/install | sh

    The curl installer verifies an Ed25519 signature on SHA256SUMS, then the SHA-256 of the archive, and installs nothing if either check fails. The release public key is in the installer, the CLI README, and https://omegacompute.com/cli/pewter-release.pub. To verify without installing:

    curl -fsSLo install.sh https://omegacompute.com/install && less install.sh && sh install.sh --dry-run

    Homebrew pins the same SHA-256 values, copied from that signed checksum list.

    2. Sign in. Run pewter login, open the device URL it prints, enter the code, and approve the request in the Pewter app. That mints a permissioned pck_ CLI key. The key is stored locally and is never printed. The CLI refuses omk_ agent keys and session tokens.

    3. Confirm:

    pewter --version    # 0.1.0
pewter status       # staging host, health ok
pewter instruments  # public catalog, no key required
pewter whoami

    The default API is https://pewter-staging-production.up.railway.app/api/v1. Any other host, including https://api.omegacompute.com/api/v1, is a hard error. Production is not enabled in v0.1.0. Available commands: login, logout, whoami, status, instruments, listings, orders, balance, verify, version, completion. connect is not part of this release.

    4. API or MCP (optional). The public CLI uses pck_ keys. MCP and POST /api/v1/agents/{id}/keys still use engine agent keys (omk_), which the CLI will not store. See MCP.

    5. Python (pewt). The package pewt is a different client from pewter / pew: a library and a pewt CLI (0.1.1). It does not log in. See Python SDK (pewt).

    More detail on the public CLI is on the Buyer CLI page.
