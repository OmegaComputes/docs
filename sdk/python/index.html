    Python SDK (pewt)¶

    pewt 0.1.1 is the buyer-side Python client and CLI for the Pewter orchestration API. It lists anonymous GPU capacity, requests an advisory quote, places and cancels orders, reads deals, and submits jobs on Test network deals. It can sign a Base Sepolia USDC payment for the paid capacity read. Version 0.1.1 does not log in, and it does not wrap seller, node, or escrow writes.

    This is not the public pewter CLI (alias pew, v0.1.0). pewter is a separate binary. pewt is the Python package: a library plus the pewt command.

    The library speaks SI workloads in plain language: you name the GPU, the count, and the hours. A capacity row does not carry a supplier identity. Rows carry seller_ref (an anonymous alias) and is_own.

    Apache-2.0. HEIR PTE. LTD. trading as Omega Compute.

    Install¶

    Python 3.9 or newer. The package classifiers list 3.9, 3.10, 3.11, 3.12, and 3.13.

    pip install pewt

    The console script is pewt. python -m pewt runs the same CLI: __main__ calls pewt.cli:main.

    pewt.__version__ is 0.1.1.

    Auth and host¶

    Point at staging

    The library default is production https://api.omegacompute.com/api/v1 (PRODUCTION_API_BASE). Set PEWTER_API_URL or base_url= until you are ready. Every example on this page uses staging.

    Staging is STAGING_API_BASE:

    https://pewter-staging-production.up.railway.app/api/v1

    export PEWTER_API_URL=https://pewter-staging-production.up.railway.app/api/v1
export PEWTER_API_KEY

    PEWTER_API_KEY is sent as Authorization: Bearer on calls that require a key. Keys are omk_ (agent), pws_ (human session), or pck_ (CLI). Pass api_key= to the constructor to override the environment variable. Do not put a key in source.

    base_url= overrides PEWTER_API_URL. The CLI flag is --base-url. timeout on the constructor, and --timeout on the CLI, default to 30 seconds.

    GET /health and GET /instruments do not send the key. The x402 helper does not send it either. It uses a separate Base Sepolia signing key, described below.

    Client¶

    from pewt import Client, STAGING_API_BASE

client = Client(base_url=STAGING_API_BASE)  # PEWTER_API_KEY from the environment
client.health()
offers = client.offers.list(gpu="H100", region="US")
quote = client.orders.quote(
    side="bid",
    instrument_id="gpu:H100:od:US:now",
    price_usd_per_unit=2.0,
    gpus=1,
    hours=1,
)
hours = client.hours.get()
jobs = client.jobs.list(deal_id="DEAL-...")
job = client.jobs.submit(
    deal_id="DEAL-...",
    runtime="container",
    image="python:3.12-slim",
    command=["python", "-c", "print(1)"],
    time_limit_s=60,
)
client.jobs.cancel(job.id)
client.close()

    price_usd_per_unit=2.0 is the limit the caller sends. It is not a published index.

    Client is also a context manager. with Client(base_url=STAGING_API_BASE) as client calls close() on the way out. Closing twice is safe. A closed client raises PewterError with code="closed".

    AsyncClient¶

    AsyncClient has the same methods as coroutines. async with calls aclose().

    import asyncio
from pewt import AsyncClient, STAGING_API_BASE

async def main():
    async with AsyncClient(base_url=STAGING_API_BASE) as client:
        offers = await client.offers.list(gpu="H100", region="US")
        print(len(offers))

asyncio.run(main())

    await client.aclose() closes without async with. Closing twice is safe.

    Responses¶

    Successful engine calls arrive as { "data": ... }. The client unwraps data. List routes return a bare array unless you pass limit and/or cursor, in which case the result is a Page: items, next_cursor, and total. limit is an integer from 1 to 200. GET /health is not wrapped; client.health() reads it directly.

    Writes other than the advisory quote send Idempotency-Key (1–80 characters). If you omit idempotency_key=, the client generates a UUID4. Send the same key again to replay the original result. POST /orders/quote does not send the header.

    Offers¶

    client.offers.list calls GET /capacity.

    Filters: kind, gpu, region, max_price, verification_min (S0, S1, S2, S3), plus limit and cursor. max_price, when set, must be a finite USD amount greater than 0 and at most 1000. Each row is an Offer: GPU model, VRAM, region, USD price per gpu_hr, assurance tier, listing id, seller_ref, and is_own. The manufacturer GPU name is the model, such as H100 or RTX 4090. The row does not include a supplier name, email, phone, or company.

    page = client.offers.list(gpu="H100", region="US", verification_min="S1", limit=20)
page.items
page.next_cursor
page.total

    Instruments¶

    client.instruments.list calls GET /instruments and does not send a key.

    Filters: gpu, term, region, limit, cursor. Each row is an Instrument. Useful instrument ids look like gpu:H100:od:US:now.

    Orders¶

    There is no separate job-quote route. A quote is POST /orders/quote. A job runs on a Test network deal after an order matches.

    orders.quote and orders.create take the same order fields. client_order_id is optional on a quote and required on create. idempotency_key applies to create only.

    Argument Required Values
    side yes bid or ask
    instrument_id yes
    price_usd_per_unit yes Caller limit. Finite, greater than 0, at most 1000. Not a published index.
    gpus yes
    hours yes
    client_order_id create only At most 80 characters
    firmness no firm or indicative
    min_fill_gpus no
    all_or_none no Boolean
    time_in_force no GTC, GTD, IOC, or FOK
    expires_at no
    contract_type no rental or purchase
    book no live or sandbox
    listing_id no
    seller_verification_min no S0–S3
    residency no List of strings
    interconnect no
    network_class no List of datacenter, colo, residential
    country no
    idempotency_key no Create only. 1–80 characters.

    The order argument is seller_verification_min. Offer search uses verification_min on offers.list. Those names are not interchangeable.

    created = client.orders.create(
    client_order_id="bid-100",
    side="bid",
    instrument_id="gpu:H100:od:US:now",
    price_usd_per_unit=2.0,
    gpus=1,
    hours=1,
    book="sandbox",
)
created.http_status  # 201, or 202 when the order is pending_approval
client.orders.get(created.order.id)
client.orders.cancel(created.order.id)

    orders.create returns the order, any deals, and http_status. orders.get returns the order and deal_ids. orders.cancel returns the order. Pass idempotency_key= to cancel when you want to choose the key.

    orders.list filters are status, side (bid or ask), instrument_id, limit, and cursor.

    Deals¶

    client.deals.list takes limit and cursor. Omit both for the array of Deal rows. client.deals.get(deal_id) returns one Deal.

    client.deals.list()
client.deals.get("DEAL-...")

    Jobs¶

    Jobs are buyer-submitted and run on Test network deals only. The server enforces that.

    client.jobs.list(deal_id) returns the jobs for that deal: jobs, can_submit, stop_reason, gpu_s_used, gpu_s_billable, and gpu_s_included. It does not take limit or cursor.

    client.jobs.submit(deal_id, *, runtime, command, time_limit_s, ...) returns a Job. Runtimes: container, mlx, pytorch-mps, llama.cpp.

    A container job needs an image such as python:3.12-slim. Native runtimes take no image. The first command token is python for mlx and pytorch-mps, and llama-cli, llama-completion, or llama-bench for llama.cpp. command is a list of 1 to 64 strings.

    env names are UPPER_SNAKE and must not start with PEWTER_. At most 32 variables. files are objects with name and content. Names are plain names (no paths), at most 8. Each content string is at most 64 KB, and the files together are at most 128 KB. time_limit_s is 10–86400. gpus, when set, is 1–64. idempotency_key is optional.

    job = client.jobs.submit(
    deal_id="DEAL-...",
    runtime="mlx",
    command=["python", "-c", "print(1)"],
    time_limit_s=60,
    env={"MODEL_NAME": "demo"},
)
client.jobs.get(job.id)

    client.jobs.cancel(job_id) returns the Job. A running cancel stops at the machine's next heartbeat. Pass idempotency_key= to choose the key.

    logs = client.jobs.logs(job.id, after=0)
while not logs.done:
    logs = client.jobs.logs(job.id, after=logs.next)
names = client.jobs.artifacts(job.id)
one = client.jobs.artifacts(job.id, name="out.txt")

    jobs.logs takes optional after (integer ≥ 0) and limit (1–1000). Poll with the returned next value until done is true. jobs.artifacts lists artifacts, or returns one artifact when name is set. A blank name is rejected.

    Hours and identity¶

    client.hours.get() calls GET /hours. unit is gpu_hours. The summary has active, negotiating, closed, and all-time counts. by_role has a buyer bucket and a seller bucket (by_role["buyer"], by_role["seller"]).

    client.me.get() calls GET /me.

    client.health() calls GET /health. It is unauthenticated liveness. The body is not a data envelope. A Health value has status, api_version, time, and uptime_s.

    Errors¶

    HTTP errors are not swallowed. Failures raise PewterError with status, code, message, request_id, and details. Timeouts raise PewterError with code="timeout". Connection failures use code="transport_error". Redirects are refused (code="redirect") and are not followed. A closed client raises code="closed".

    from pewt import Client, PewterError, STAGING_API_BASE

with Client(base_url=STAGING_API_BASE) as client:
    try:
        client.orders.get("ORD-...")
    except PewterError as exc:
        print(exc.status, exc.code, exc.message, exc.request_id, exc.details)

    X402Error is a PewterError for a refused payment requirement or a lingering HTTP 402. X402ConfigError is an X402Error raised when the Base Sepolia signing key is missing or is not a 32-byte hex key. except PewterError catches both.

    x402 on Base Sepolia¶

    client.x402.capacity(...) calls GET /api/v1/x402/capacity (same filters and rows as offers.list). An unpaid request is HTTP 402. The helper checks the requirement, signs an EIP-3009 transferWithAuthorization, and retries once with PAYMENT-SIGNATURE.

    This is Test network only. The helper does not send PEWTER_API_KEY.

    • Chain: Base Sepolia, CAIP eip155:84532, chain id 84532.
    • Asset: Circle USDC 0x036CbD53842c5426634e7929541eC2318f3dCF7e (name USDC, version 2, 6 decimals).
    • The helper refuses Base mainnet (chain id 8453), mainnet USDC 0x833589fCD6eBd6E08f4c7C32D4f71b54bdA02913, and the Pewter staging test token 0xd4822Fa535d1784F880969f0E7Ef5c3A209CdF20 (no EIP-3009).
    • It pays the amount in the 402, and refuses anything above 1 USDC.
    • The signing key comes from PEWTER_X402_TEST_PRIVATE_KEY or x402_private_key=. There is no default wallet. The key is never logged. The server settles; this client does not call the facilitator.
    from pewt import Client, STAGING_API_BASE

client = Client(base_url=STAGING_API_BASE)
rows = client.x402.capacity(gpu="H100")
result = client.x402.call_tool("list_capacity", {"gpu": "H100"})
client.close()

    call_tool posts one JSON-RPC tools/call and returns that object. It does not unwrap a data envelope. Names are limited to list_capacity, resolve_requirements, get_quotes, get_market_summary, and get_price_history. Any other name is refused locally, including writes and account tools. An optional request_id= defaults to 1. Offer search for buyers stays on offers.list.

    CLI¶

    Global flags: --base-url and --timeout (seconds, default 30). When --base-url and PEWTER_API_URL are both unset, the CLI uses the production library default. Point it at staging.

    export PEWTER_API_URL=https://pewter-staging-production.up.railway.app/api/v1
export PEWTER_API_KEY

pewt --base-url "$PEWTER_API_URL" status
pewt offers --gpu H100 --region US --verification-min S1
pewt instruments --gpu H100 --limit 5
pewt quote --side bid --instrument-id gpu:H100:od:US:now --price 2 --gpus 1 --hours 1
pewt orders create --client-order-id bid-100 --side bid --instrument-id gpu:H100:od:US:now --price 2 --gpus 1 --hours 1 --book sandbox
pewt orders list --side bid
pewt deals list
pewt jobs --deal DEAL-...
pewt jobs submit --deal DEAL-... --runtime container --image python:3.12-slim \
  --command python --command=-c --command 'print(1)' --time-limit 60
pewt jobs logs JOB-...
pewt jobs cancel JOB-...
pewt hours
pewt whoami

    --price is the caller limit (price_usd_per_unit), not a published index. The 2 above is that limit.

    pewt offers prints the manufacturer GPU name, count, VRAM, country or region, USD price per GPU-hour, verification tier, listing id, seller_ref, and is_own. It does not print a supplier name, email, phone, or company.

    pewt status prints the configured host and health. pewt whoami is GET /me. pewt hours prints unit (gpu_hours) and the active, negotiating, closed, and all-time figures, including buyer and seller totals. pewt instruments needs no API key.

    Commands and flags:

    Command Flags
    offers --kind, --gpu, --region, --max-price, --verification-min (S0–S3), --limit, --cursor
    instruments --gpu, --term, --region, --limit, --cursor
    status none
    whoami none
    hours none
    quote Order flags below. --client-order-id is optional. No idempotency flag.
    orders list --status, --side (bid or ask), --instrument-id, --limit, --cursor
    orders get order_id (id or client_order_id)
    orders cancel order_id, --idempotency-key
    orders create --client-order-id (required) and the order flags below, plus --idempotency-key
    deals list --limit, --cursor
    deals get deal_id
    jobs --deal lists jobs when no subcommand is given
    jobs list --deal (required)
    jobs get job_id
    jobs submit --deal, --runtime (container, mlx, pytorch-mps, llama.cpp), repeated --command, --time-limit, optional --image, --gpus, repeated --env NAME=VALUE, repeated --file name=local-path, --idempotency-key
    jobs cancel job_id, --idempotency-key
    jobs logs job_id, --after, --limit
    jobs artifacts job_id, --name

    pewt orders and pewt deals need a subcommand. pewt jobs needs --deal or a subcommand (list, get, submit, cancel, logs, artifacts).

    Order flags on quote and orders create: --side, --instrument-id, --price, --gpus, --hours, --firmness (firm or indicative), --min-fill-gpus, --all-or-none, --time-in-force (GTC, GTD, IOC, FOK), --expires-at, --contract-type (rental or purchase), --book (live or sandbox), --listing-id, --verification-min (S0–S3), repeated --residency, --interconnect, repeated --network-class (datacenter, colo, or residential), --country. --verification-min on these commands is seller_verification_min. On offers the same flag is the capacity filter verification_min.

    --all-or-none is a switch. Omit it to leave the field unset. Repeat --command once per token. A token that starts with a dash is --command=-c. --image is required for container and forbidden for native runtimes. --file reads a local UTF-8 file. The name on the left of = is a plain file name, with no directory.

    --limit and --cursor opt into a page. Omit both for the legacy array. Commands that page are offers, instruments, orders list, and deals list.
