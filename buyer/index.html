    Buyer CLI¶

    The public Pewter CLI is pewter (alias pew), version 0.1.0. It is read-only. It talks only to the Pewter staging API and refuses production, including api.omegacompute.com. Account calls use a permissioned pck_ API key, minted only after someone who already has a Pewter account approves a device login in the Pewter app.

    HEIR PTE. LTD., trading as Omega Compute, publishes the signed release from OmegaComputes/pewter.

    pewter is not pewt. The Python package pewt 0.1.1 is a library and a pewt command for the orchestration API. It does not log in. This page is only the pewter / pew CLI.

    Install¶

    On macOS (the supported Mac install; darwin binaries in 0.1.0 are not notarized):

    brew trust --formula omegacomputes/tap/pewter   # Homebrew 7; required before the formula will load
brew install omegacomputes/tap/pewter

    On Linux, and on macOS once OpenSSL 3 is first on PATH:

    curl -fsSL https://omegacompute.com/install | sh

    Prefer to read the installer first?

    curl -fsSLo install.sh https://omegacompute.com/install && less install.sh && sh install.sh

    Both commands install pewter and the pew alias. Options on the curl installer include --version X.Y.Z, --dir DIR, --dry-run (verify only) and --verbose.

    Verify the signature¶

    The curl installer downloads the archive from https://omegacompute.com/cli/, checks an Ed25519 signature on SHA256SUMS with a public key built into the installer, then checks the SHA-256 of the archive against that list. If the signature, the checksum, or the archive contents fail, nothing is installed.

    The same public key is in the CLI README and at https://omegacompute.com/cli/pewter-release.pub, so you can compare them. To verify without installing:

    curl -fsSLo install.sh https://omegacompute.com/install && less install.sh && sh install.sh --dry-run

    That should end with Dry run: pewter v0.1.0 verified. Nothing was installed.

    Homebrew does not check the Ed25519 signature itself. The formula pins the SHA-256 of each archive, copied from SHA256SUMS only after that signature was verified.

    Sign in and the staging host¶

    Public sign-up is not open. You need an existing Pewter app account.

    pewter login

    The command prints a device URL and a short code on stderr. Open the URL, enter the code, and approve the request in the Pewter app. That mints a pck_ CLI credential: hashed on the server, scoped, revocable, with a 90-day life. The access token is stored locally and is never printed. The CLI accepts only pck_ keys. It refuses omk_ agent keys and session tokens, and it will not store them.

    pewter --version
pewter status
pewter whoami

    pewter --version should report 0.1.0. pewter status can run with no key and should show the staging host as healthy. pewter instruments is a public catalog and also needs no key. pewter whoami without a key exits 3.

    The default API is:

    https://pewter-staging-production.up.railway.app/api/v1

    That host is the staging orchestration. Account data there is not the live book. Loopback is allowed for tests. Any other host, including https://api.omegacompute.com/api/v1, is a hard error (exit 2). Production is not enabled in this release.

    pewter logout revokes the credential on the server, then deletes the local copy.

    Commands¶

    Available in v0.1.0: login, logout, whoami, status, instruments, listings, orders, balance, verify, version, completion.

    connect, pay, and the seller agent are not part of this release. Buyers who need HTTP or an assistant integration can still use the API or the MCP server. Those paths use engine agent keys (omk_), which the public CLI will not store.
